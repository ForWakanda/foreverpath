# Hearth & Hustle — rules for AI coding sessions (Claude Code, Codex, cloud sessions)

This file is loaded automatically by Claude Code. It carries the durable engineering rules for this repo so a fresh session, local or cloud, can work safely without any other context.

## What this is
A World of Warcraft: Forever addon: quest GPS + route planner + profession help + PvP HUD, plus a recorder. Since v0.28.0 the recorder keeps only what a feature reads back (`settings.record`); the research dataset is a second, opt-in level (`settings.recordDataset`). Before adding a recorded field, name the feature that reads it, or put it behind the dataset switch. Lua 5.1 (WoW's dialect), interface 16001 (Forever release; the client was 1.60.1.70790 at the last data pull, Blizzard's `forever` source was at 70938 on 2026-11-13 — re-check `version.txt` after every patch). Design, verified API facts and phases: `docs/SPEC.md`.

## Hard rules
- Shared questing, dungeon, profession, trainer, reward and preparation tools must work regardless of the player's class. Gate specialized helpers by the current character; do not assume a Mage/Hunter pair, Enhancement spec or duo play. Custom joke/action sounds were retired at the user's request (2026-11-10); keep them out of the addon.
- **No automation, ever.** The addon shows information; the player acts. No inputs, targeting, casting, looting, turn-ins, or decisions driven by combat data. This is Blizzard's line and the project's.
- **Two sanctioned background writes, each the owner's decision. Do not widen either to other state, and do not add a third without the owner's word.**
  - Action bar layout (`Modules/BarGuard.lua`, 2026-11-13). It puts remembered buttons back on slots the server emptied: empty slots only, never in combat, never while the cursor holds something, never replacing or removing a button, never using one.
  - The quest item sparkle setting (`Modules/QuestSparkle.lua`, 2026-11-14). It keeps one console variable, `outlineModeShowLootEffectWhenDisabled`, switched on: never in combat, never Outline Mode or any other console variable, and no general `SetCVar` function in the adapter. Switched off, it restores only a value it changed itself.
- **Enemy watch (`PvP/EnemyWatch.lua`, owner's request 2026-11-14) only reports players the client already shows** (nameplate, target, focus, mouseover). Its stealth notice is the one place the addon reads another player's cast: four spells, readable values only, nothing timed. Do not grow it into cooldown, diminishing-returns or interrupt tracking of enemies, do not add targeting, and write the nameplate settings only on the player's click.
- **Nearby-object sparkles are retired (v0.27.1, owner's report 2026-11-16). Do not rebuild them.** v0.27.0 drew an extra sparkle on the one object the game's Interact Key selects. That needs the Interact Key mode (`SoftTargetInteract` 3 and its display settings), reaches about 15 yards, and changes who an untargeted heal or buff lands on. `Modules/NearbySparkle.lua` is now only the undo: at login, out of combat, it puts back each of those settings that is still at the value setup gave it, from the list setup saved, then forgets the list. The adapter refuses the setup values, so nothing can switch the mode on. No sparkle, outline or marker through soft targeting, for quest objects, herbs, ore or corpses. The game draws its own sparkle only on objects it chooses, and an addon cannot add one.
- **Forever's secret values are real.** In combat, enemy casts/auras, and even your own cooldowns/auras, come back as secret values that throw on comparison. Every unit read goes through `FP.safe()`; never branch on a possibly-secret value; never register `COMBAT_LOG_EVENT_UNFILTERED`; never call `C_SuperTrack.SetSuperTrackedUserWaypoint`. The verified gate table is in the spec §2/§8.
- **Only `HearthAndHustle/API/Adapter.lua` calls gameplay WoW APIs.** Feature-detect everything (`has(C_QuestLog, "GetInfo")`), so a renamed function on the next build degrades one feature instead of breaking the addon. UI/framework calls (CreateFrame, fonts, timers) are fine anywhere.
- **Verify against Blizzard's own Forever UI source**, not Classic-era memory: `git clone --depth 1 --branch forever https://github.com/Gethe/wow-ui-source.git` and grep `Interface/AddOns/Blizzard_APIDocumentationGenerated/`.
- **`tools/check.sh` must be green before any commit that touches `HearthAndHustle/`.** It runs `luac -p` on every file, validates XML/TOC, the mock play-through (`tests/run.lua`) and the regression suite (`tests/regressions.py`). Run it unpiped and gate on its exit code; never judge a check through `| tail`.
- **In-game truth beats the mock.** Nothing here can run the game. `HearthAndHustleDB.errors` and `HearthAndHustleDB.apicheck` (SavedVariables) are the evidence after a session; read them before changing code. A null result from an unverified API is not evidence.
- Lua 5.1 only: no `goto`, no `//`, no `\z`. WoW's global `atan2`/`sin`/`cos` use degrees; use `math.*`. SavedVariables are created inside `ADDON_LOADED`, never at file scope.
- Keep it free, open, unobfuscated, ad-free (Blizzard UI Add-On Development Policy). MIT.
- **Renamed from "ForeverPath" in v0.17.0** because an unrelated addon now uses that name, the same SavedVariables names and `/fp`. Never register `/fp` or reuse the old global names. Old data is adopted only through the schema check in `Core/Config.lua` (`adoptLegacy`) or `tools/migrate-from-foreverpath.py`; a table that merely has the old variable name may belong to the other addon.

## Layout
`HearthAndHustle/` is the addon (what gets installed). `Core/` namespace, config, util · `API/Adapter.lua` the only gameplay API surface · `Nav/` position, waypoints, arrow, map pins (and, on the world map, the route a quest target walks or the outline of the area it roams: plain lines on the canvas under the markers, from the quest database's `waypoints`; an outline only for a target needed once from one creature, never a path between its recorded places; the pin level manager is only read) · `Data/Recorder.lua` telemetry (two levels; the one-time prune of older profiles is `FP.SlimSave` in `Core/Config.lua`, schema 3) · `Route/Planner.lua` · `Route/Travel.lua` sea crossings, known flight points, trip plan (read-only; reference positions, never a new waypoint without a click) · `Prof/Tracker.lua` · `Party/Sync.lua` · `Modules/Gear.lua` + `UI/Gear.lua` gear finder (the role browsed on the page, `gear.browse`, is not the character's role, `gear.profile`: only the "Make … my role" button writes the latter; the Windfury burst sort is for a shaman browsing melee main-hand weapons and shows where each of its numbers came from; the bundled reference lacks about a fifth of the quest rewards and most listed dungeon drops, so the page adds "live" items — the rewards of quests in the log and what the quest database names — whose slot, quality and stats are read from the client by item id, a few per tick, out of combat, never shipped and never saved; a search looks in every slot; `Modules/QuestRewards.lua` ranks a quest's rewards per role with the same scores) · `Modules/` cosmetic/diagnostic modules, plus `Healer.lua` (heal rank table and between-pull party check: out of combat only, never health/mana/auras) and `Dungeons.lua` (dungeon quest checklist: where each quest starts is asked of the installed quest database first — giver and place, or the starting item and what drops it, inside a dungeon or not — and a quest behind a chain names the step that opens it; the bundled catalogue is the fallback and its placeholders never reach the page; a quest the database lists under two numbers, exclusive and same-named, is recognised in the log or completed under either, `D:Variants`, so never ask the client about a catalogue id alone; the window's list is `D:Todo`, what a giver hands over today first — dungeon quests and the first step of each chain, nearest first with giver, place and distance — then the log, then what comes later; the Dungeons page has ONE chosen dungeon: a click in the ranking or in the itinerary list sets both) and `DungeonPlan.lua` (dungeon itinerary, and the "which dungeon next" ranking for the own role plus a second spec, `gear.second`, measured against the best gear carried, worn or in the bags; read-only until a click) · `PvP/` HUD, own-cast timers, roster, enemy watch, battleground, coordination · `UI/` panel + `/hh` commands. `tests/` mock harness. `tools/check.sh` gate, `tools/deploy.sh` local install (Windows WoW path via WSL), `tools/pull-data.sh` dataset export, `tools/install-questiedb.py` the checksum-pinned quest database (QuestieDB 1.1.3; `--update --backup DIR` replaces an older copy with the game closed; a newer release is adopted by changing the pin after `tests/questiedb-integration.lua` passes against it).

## Toolchain
Lua 5.1: `apt-get install -y lua5.1` on Debian/Ubuntu (binaries `lua5.1`, `luac5.1`) or build from lua.org (`make generic`). Set `LUA`/`LUAC` for `tools/check.sh` if they are not at `~/.local/bin`. Python 3 for the regression suite and tooling. No other dependencies.

## Working agreement
- One feature or fix per commit; describe the in-game verification status honestly (mock-tested vs game-verified).
- Add or extend a `tests/run.lua` scenario or `tests/regressions.py` check with every behaviour change.
- New sound/texture files need a full game client restart, not `/reload`.
- Update `docs/SPEC.md` when an API fact is verified or falsified in game.
